# NiceECatM 使用说明

[English](README.md) | **简体中文**

NiceECatM 是 EtherCAT 图形测试工具，提供从站扫描、状态控制、PDO 信号测试、ESC 寄存器与 CoE SDO 访问，以及 Lua 脚本自动化。

项目主页：[NiceECatM on GitHub](https://github.com/NaisuXu/NiceECatM)

## 开始使用

1. 将 Windows x64 ZIP 解压到可写目录，运行 `NiceECatM.exe`，并将随附目录保留在可执行文件旁。
2. Windows 访问真实设备时，单独安装 [Npcap](https://npcap.com/#download)，或使用兼容的 WinPcap。如果驱动限制管理员访问，则以相应权限启动。
3. 使用右上角 **EN** / **中文** 切换语言，默认使用英文。

无需硬件体验时，在断开状态下选择**连接配置**中的**模拟设备**，再点击**扫描设备**。默认使用**真实设备**。Linux 需对应二进制文件和原始以太网权限，当前 ZIP 仅包含 Windows x64 应用。

## Windows / Intel 网卡设置

建议将 EtherCAT 专用 Intel 有线网卡的 **Interrupt Moderation（中断调节/中断节流）** 设为 **Disabled（禁用）**，以降低收包延迟。

打开**设备管理器 → 网络适配器 → 对应的 Intel 网卡 → 属性 → 高级**，选择 **Interrupt Moderation（中断调节/中断节流）**，设为**禁用**并应用。待链路恢复后重新扫描。选项名称随驱动而异，未提供该选项时跳过。

Intel I219-LM 实测中，关闭该选项降低了典型收包延迟。效果取决于网卡和驱动，不能保证达到目标周期或消除 WKC 异常；请在**诊断**中确认实际时序和 WKC。

## 基本操作

1. 选择**真实设备**、**单网口**、**普通映射**及连接从站的有线网卡，再点击**扫描设备**。扫描成功后从站处于 **PRE-OP**，周期 I/O 停止。
2. 在左侧拓扑选择从站，**Buffer · PDO** 显示其信号；输入只读，已映射输出可直接编辑。
3. **SAFE-OP** 启动周期交换，从站输出保持安全状态；**OP** 允许应用输出数据。**INIT** / **PRE-OP** 停止周期交换，**断开连接**同时关闭连接。

同步访问 ESC 寄存器或 CoE SDO 前先请求 **PRE-OP**，因为这些操作要求停止周期交换。通过**诊断**和全局**日志**查看实际状态与错误；选中一条日志后按 **Ctrl+C** 复制。

目标周期默认 **10 ms**，可选 **500 us、1、2、5、10、20、50、100 ms**。断开时，或周期已停止且所有从站处于 INIT/PRE-OP 时，可修改周期；实际时序以诊断显示为准。

**更改前先断开连接：** 真实/模拟模式、网卡、冗余和映射方式。双口冗余的两个接口接在**同一从站链**两端；普通/重叠映射与网口数量独立。

需要信号描述时，将匹配的厂商 ESI XML 放入 `esi/`，重启后重新扫描。只有英文的设备名称在中文界面仍保留英文。

## Lua 脚本

脚本是相邻 `scripts/` 目录中的 UTF-8 `.lua` 文件。脚本页提供编辑器、文件列表、格式化和 API 片段；片段只插入代码，不执行。

1. 选择文件，或点击**新建**创建一个名称不重复的草稿。
2. 双击列表文件名可重命名；名称前的 `*` 表示文件或编辑内容未保存。
3. 编辑后先**保存**再**运行**。未保存源码会被拒绝，不会静默执行旧的已保存内容。
4. 在全局**日志**查看输出和错误。同一时间只运行一个脚本。
5. 脚本**停止**按钮终止其回调和任务，不会自动断开总线或停止周期 I/O。

未保存编辑只存在于内存，退出后丢失。**打开 / 重新加载**从磁盘读取选中文件，丢弃其缓存编辑。切换到其他文件不会停止正在运行的脚本。

保存并运行下面的代码，可以检查当前工作台连接，不会打开另一条连接：

```lua
local bus = ecat.current()
local status = bus:status()
assert(status.connected, "scan the bus first")
log.info(string.format("state=%s WKC=%d/%d",
    status.state, status.wkc, status.expected_wkc))
```

随包示例的作用各不相同：

| 文件 | 行为 |
| --- | --- |
| `Example_01_Full_Lifecycle.lua` | 从断开状态开始；枚举真实网卡并使用第一张及当前冗余/映射设置，扫描、查看设备、进入 OP，再返回 PRE-OP 并断开；应按实际总线调整连接参数 |
| `Example_02_Signal_Inspection.lua` | 要求当前连接已扫描并映射；查看信号和输入值后结束，周期停止时读到缓存值 |
| `Example_03_Cycle_Automation.lua` | 要求周期 I/O 已运行；每十个观察到的周期报告一次并定时输出心跳，持续到手动停止 |
| `Example_04_Output_Write_Test.lua` | 要求已映射且找到可写的标量输出；将首个输出写为零后结束，运行前应确认目标；无输出或不满足写入条件时会报错 |
| `Example_05_State_Sequence.lua` | 要求当前连接及映射有效；依次请求 INIT/PRE-OP/SAFE-OP/OP，在单次定时器触发后返回 PRE-OP 并断开 |

示例失败会记录日志，并可能让总线保持连接及最后到达的状态。请检查实际状态，按需请求 PRE-OP 或断开连接。

`ecat.current()` 取得当前工作台连接。`ecat.open(...)` 选择连接参数，`bus:scan()` 才执行扫描。总线调用直接返回结果，不需要 `await` 包装。按唯一信号名或 Index/SubIndex 定位，不要假定 `Input` 之类名称唯一。

定时器使用毫秒，周期回调使用正整数**周期数**。`cycle.every(1, fn)` 跟随观察到的周期，`cycle.every(2, fn)` 等待经过两个周期。定时和周期注册都返回可取消的任务 ID；它们在脚本工作线程运行，可能跳过中间总线周期，不能替代硬实时控制循环。

重复定时器或周期任务会在顶层代码执行完后保持脚本运行。无剩余任务或被停止时，脚本结束。`bus:stop()` 停止总线 I/O，脚本停止按钮停止脚本。用 `timer.cancel(id)` 或 `cycle.cancel(id)` 取消单个任务；更多代码可参考页面中的 API 片段和随包示例。

## 文件与升级

- `scripts/`：已保存的 Lua 文件及五个示例；`esi/`：厂商 XML 描述。
- `preferences.ini`：仅保存界面语言。以上文件均以可执行文件目录为准，重启后需重新选择连接参数。
- 升级前关闭软件，备份 `scripts/`、自定义 `esi/` 文件和 `preferences.ini`。将新版本解压到新目录，再复制需要保留的数据。
